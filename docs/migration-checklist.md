# העברת המערכת למופע n8n חדש

מדריך זה נכתב אחרי העברה אמיתית. הסדר חשוב — כמה מהשלבים לא ניתנים
לביצוע אחרי שהמכסה במופע הישן נגמרת.

---

## 1. ייצוא — במופע הישן, בזמן שהוא עוד עובד

בכל אחד מעשרת ה-Workflows: `...` → **Download**.

שמור לתיקייה `workflows/` ודרוס את הקבצים הקיימים. הקבצים בריפו
מתיישנים בכל שינוי, ובמיוחד WF8 ו-WF13 שהשתנו הכי הרבה.

**קובצי הייצוא אינם מכילים מפתחות** — רק את שמות ה-credentials.

---

## 2. ייבוא במופע החדש

1. `...` → **Import from File** לכל אחד מעשרת הקבצים
2. צור מחדש את כל הקרדנציאלים — הם לא עוברים בייצוא:

| קרדנציאל | משמש ב- |
|---|---|
| Airtable OAuth2 | WF1, WF3, WF4a, WF4b, WF8, WF9, WF13 |
| OpenAI | WF5, WF6, WF7, WF9, WF13 |
| Gmail | WF4a, WF4b |
| Google Drive | WF8 |
| Telegram — בוט המנהל | WF9 |
| Telegram — בוט הלקוחות | WF5 |

3. בכל נוד שמסומן בסימן קריאה — בחר את הקרדנציאל החדש

**שני הקרדנציאלים של טלגרם חייבים להחזיק שני טוקנים שונים.**
זו המלכודת הכי שקטה בהעברה כולה: קל להדביק בטעות את אותו טוקן בשניהם,
ואז n8n לא מתלונן, שום נוד לא מסומן באדום, ושום הרצה לא נכשלת.

מה שקורה בפועל: לטלגרם מותר webhook אחד לכל בוט, אז WF5 ו-WF9 נלחמים
על אותו בוט — **מי שהופעל אחרון מנצח והשני מפסיק לקבל הודעות בשקט.**
התסמין מטעה: בוט אחד עובד מצוין, השני פשוט שותק, וקל להאשים את
שער הזהות או את הסוכן.

איך מוודאים: @BotFather ← `/mybots` ← כל בוט בנפרד ← `API Token`,
ולהשוות שהטוקנים באמת שונים. אם אחד מהבוטים שותק אחרי ההעברה —
ספירת ההרצות שלו תהיה **אפס**, וזה הסימן.

---

## 3. הרשאות דומיין לקרדנציאלים

**זה השלב שהכי קל לשכוח, והוא מפיל שני Workflows בשקט.**

n8n → **Settings** → **Credentials** → פתח את הקרדנציאל → **Details** →
שדה **Allowed HTTP Request Domains** → `Specific Domains`:

| קרדנציאל | דומיין להזין | למה |
|---|---|---|
| Google Drive | `googleapis.com` | WF8 — נוד HTTP שממיר את החשבונית למסמך Google |
| Airtable | `api.airtable.com` | WF13 — נוד HTTP שמעדכן רשומות |

כברירת מחדל n8n חוסם שימוש בקרדנציאל מתוך נוד HTTP Request. בלי
ההגדרה הזו שני הנודים נכשלים בהרשאה.

---

## 4. כתובת ה-Webhook משתנה

מזהה ה-Webhook נוצר מחדש בכל מופע. אחרי **Publish** ל-WF13, העתק את
ה-Production URL ועדכן אותו בשלושה מקומות:

- `dashboard.html` — הקבוע `API` בראש הקובץ. **ואז commit ו-push**,
  אחרת לוח הבקרה החי מפסיק לעבוד
- אפליקציית הניהול
- `docs/api-contract.md`

אותו דבר ל-WF3 אם הטופס החיצוני מצביע אליו.

---

## 5. הפעלה

- **Publish** לכל מה שהיה פעיל: WF1, WF3, WF4a, WF4b, WF5, WF8, WF9, WF13
- **הרץ ידנית את WF6 ואת WF7.** המאגרים הווקטוריים יושבים בזיכרון של
  n8n ונמחקים בכל מופע חדש. בלעדיהם שני הבוטים עונים בלי מקורות
- **WF8** — ודא שה-Schedule Trigger על שעה ולא על דקה. טריגר דקתי
  צורך כ-1,440 executions ביום ומרוקן מכסה חינמית בפחות משבוע
